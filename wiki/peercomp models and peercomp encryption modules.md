## @peercomp/models and @peercomp/encryption

Relevant source files

This page documents the shared workspace packages that provide the data backbone and security primitives for the PeerComp platform. defines the Mongoose schemas and TypeScript interfaces used by the Org API and other backend services. provides the cryptographic implementation for identity management, signing, and end-to-end encryption (E2EE) for the Key-Value store.

## @peercomp/models

The package centralizes the database schema definitions to ensure consistency across the monorepo. It uses Mongoose to interact with MongoDB and exports the models along with a utility function [packages/models/src/index.ts#6-11](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/index.ts#L6-L11)

### Model Definitions

#### 1\. UserModel

The model represents a platform participant. It uniquely identifies users via a 256-bit hexadecimal string, which is generated using to serve as a DHT-compatible node identifier [packages/models/src/user.model.ts#2-11](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/user.model.ts#L2-L11)

| Field | Type | Description |
| --- | --- | --- |
|  |  | 256-bit Node ID (Hex) |
|  |  | Unique username |
|  |  | Unique email address |
|  |  | Hashed password |
|  |  | "admin" or "user" |
|  |  | Optional storage for serialized identity keys |

Sources: [packages/models/src/user.model.ts#10-22](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/user.model.ts#L10-L22)

#### 2\. FunctionModel

Stores metadata and source code for user-defined serverless functions. It uses a composite unique index on,, and to prevent collisions within the same user context [packages/models/src/function.model.ts#16-19](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/function.model.ts#L16-L19)

| Field | Type | Description |
| --- | --- | --- |
|  |  | Friendly name |
|  |  | The URI path (e.g., "/hello") |
|  |  | "GET" or "POST" |
|  |  | The JavaScript source code |
|  |  | Reference to User |
|  |  | User-specific namespace for DHT lookups |

Sources: [packages/models/src/function.model.ts#3-13](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/function.model.ts#L3-L13)

#### 3\. KVModel

Stores arbitrary data for the distributed key-value store. It supports both plaintext and encrypted values.

| Field | Type | Description |
| --- | --- | --- |
|  |  | The lookup key |
|  |  | Flag for E2EE |
|  |  | The AES-GCM ciphertext |
|  |  | Initialization Vector for decryption |
|  |  | Reference to User |

Sources: [packages/models/src/kv.model.ts#2-14](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/models/src/kv.model.ts#L2-L14)

## @peercomp/encryption

The package implements the security protocol for the platform, focusing on Identity Keys (ECDSA) and Session Keys (ECDH).

### IdentityKey Class

The class manages long-term cryptographic identities using the P-256 curve [packages/encryption/utils.ts.bac#63](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/encryption/utils.ts.bac#L63-L63) It is responsible for:

- Generation: Creating new ECDSA key pairs [packages/encryption/utils.ts.bac#61-68](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/encryption/utils.ts.bac#L61-L68)
- Signing/Verification: Ensuring data integrity and authenticity [packages/encryption/utils.ts.bac#107-123](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/encryption/utils.ts.bac#L107-L123)
- Serialization: Exporting to format (Base64 SPKI/PKCS8) for storage in IndexedDB or MongoDB [packages/encryption/utils.ts.bac#95-104](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/packages/encryption/utils.ts.bac#L95-L104)
