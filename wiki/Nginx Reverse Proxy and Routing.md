## Nginx Reverse Proxy and Routing

Relevant source files

The Nginx configuration serves as the unified entry point for the PeerComp ecosystem. It handles SSL termination, redirects insecure traffic, and implements a sophisticated routing logic that distinguishes between the primary management interface and dynamically routed tenant subdomains for serverless function execution.

## System Architecture and Request Flow

Nginx operates in network mode within the Docker stack, allowing it to interface directly with services bound to the loopback interface on the host machine [apps/backbone/docker-compose.yaml#34](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/docker-compose.yaml#L34-L34)

### Request Routing Logic

The configuration is split into two primary functional blocks based on the directive:

1. Main Domain Management: Routes traffic for to the Vite frontend, Org API, and signaling services [apps/backbone/nginx/nginx.conf#24](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/nginx/nginx.conf#L24-L24)
2. Wildcard Tenant Routing: Captures any subdomain (e.g., ) and forwards it to the Gateway Node for function execution [apps/backbone/nginx/nginx.conf#79](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/nginx/nginx.conf#L79-L79)
