## Authentication and Authorization

Relevant source files

The PeerComp platform utilizes a JSON Web Token (JWT) based authentication mechanism to secure interactions between the frontend application and the Org API service. This system ensures that user identities are verified before allowing access to protected resources such as serverless functions and key-value storage.

## Authentication Flow

The authentication process begins with user registration or login through the service. Upon successful verification of credentials, the server issues a JWT signed with a secret key.

### Login and Token Generation

When a user provides their email and password, the method [apps/org/src/controller/user.controller.ts#22-30](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/org/src/controller/user.controller.ts#L22-L30) delegates the request to the. The method performs the following steps:

1. User Verification: Searches for the user in MongoDB by email.
2. Password Validation: Compares the provided password against the stored bcrypt hash.
3. JWT Signing: Generates a token containing the and as payload, signed with a secret key.

### User Registration

The method [apps/org/src/controller/user.controller.ts#6-20](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/org/src/controller/user.controller.ts#L6-L20) handles the ingestion of user details (,,,, ) from the request body. The underlying service handles:

1. Salting and Hashing: Uses to hash the password before storage.
2. Persistence: Saves the new user model to the database.
3. Auto-Login: Returns a valid token immediately upon successful creation.

## Client-Side Token Management

The web frontend manages the lifecycle of the JWT using Zustand for state management and a dedicated PanelGuard component for route protection.

### Persistence with Zustand

The store [apps/web/app/lib/store/index.ts#9-20](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/lib/store/index.ts#L9-L20) utilizes the middleware to synchronize the authentication token with. This ensures that the user remains logged in across browser refreshes. The store is named [apps/web/app/lib/store/index.ts#16](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/lib/store/index.ts#L16-L16)

Additionally, the frontend manages cryptographic identity through the store [apps/web/app/lib/store/index.ts#27-38](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/lib/store/index.ts#L27-L38) which persists the user's to under the key [apps/web/app/lib/store/index.ts#34](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/lib/store/index.ts#L34-L34) These keys can be managed via the component [apps/web/app/pages/panel/components/settingsKeyPairCard.tsx#14-78](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/pages/panel/components/settingsKeyPairCard.tsx#L14-L78)

### Frontend Guarding (PanelGuard)

The component [apps/web/app/components/panelGuard.tsx#6-49](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L6-L49) acts as a client-side middleware for protected routes. It performs several validation steps:

1. Existence Check: If no token is found in, it redirects to [apps/web/app/components/panelGuard.tsx#10](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L10-L10)
2. Token Verification: It calls the endpoint [apps/web/app/components/panelGuard.tsx#12](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L12-L12) using the token schema [apps/web/app/components/panelGuard.tsx#15](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L15-L15)
3. Identity Verification: It further validates the token by calling the endpoint [apps/web/app/components/panelGuard.tsx#22](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L22-L22)
4. Expiry Check: It compares the (expiration) claim from the token data against the current time () [apps/web/app/components/panelGuard.tsx#39](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L39-L39) If the token is expired, it triggers a redirect [apps/web/app/components/panelGuard.tsx#40](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/web/app/components/panelGuard.tsx#L40-L40)
