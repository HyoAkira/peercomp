## End-to-End Encryption for KV Storage

Relevant source files

This page details the security architecture for the PeerComp Key-Value (KV) storage system. PeerComp implements an end-to-end encryption (E2EE) model where sensitive data is encrypted on the client side before being transmitted to the Org API or stored in MongoDB. This ensures that even if the central database is compromised, the actual values remain unreadable without the corresponding keys.

## Encryption Architecture Overview

The encryption system relies on three primary cryptographic primitives:

1. ECDH (Elliptic Curve Diffie-Hellman): Used for secure key agreement between peers using the curve.
2. ECDSA (Elliptic Curve Digital Signature Algorithm): Used for identity verification and signing public keys to prevent Man-in-the-Middle (MITM) attacks.
3. AES-GCM (Advanced Encryption Standard in Galois/Counter Mode): Used for the actual encryption of KV values, providing both confidentiality and authenticity (AEAD).
