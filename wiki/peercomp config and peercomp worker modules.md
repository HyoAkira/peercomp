## Shared Configuration Package (@peercomp/config)

The package serves as the central source of truth for the entire PeerComp monorepo. It defines the network topology, service endpoints, and resource paths used by both frontend applications and backend services to ensure consistent communication across the distributed system.

### Purpose and Scope

In a microservices architecture involving a web frontend, a P2P signaling server, and a REST API, hardcoding URLs leads to maintenance overhead and deployment errors. centralizes these constants into a single JSON-based configuration that is exported as a typed object. This allows for seamless transitions between development and production environments by updating a single file.

The package primarily exposes the object, which contains:

- Base URL: The root domain for all services (e.g., ).
- Service Paths: Specific endpoints for the signaling server, peer discovery, and the core Org API.
- Database URIs: Connection strings for MongoDB used by backend services.
