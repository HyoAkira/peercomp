## Infrastructure and Backbone

Relevant source files

The Infrastructure and Backbone layer provides the foundational services required for the PeerComp platform to operate. This layer is responsible for container orchestration, persistent storage, secure communication via TLS, and intelligent request routing across the monorepo's various services.

## System Architecture Overview

The backbone is managed primarily through Docker Compose, which orchestrates the core data layer and the entry-point reverse proxy. While the application services (Org API, Peer Signal, etc.) can run natively for development, they are unified behind a centralized Nginx configuration that handles SSL termination and service discovery.

## Nginx Reverse Proxy and Routing

Nginx acts as the gatekeeper for the entire platform. It is configured to handle two primary types of traffic:

1. Main Domain Traffic: Directs requests for to the Vite frontend or specific API endpoints.
2. Wildcard Subdomain Traffic: Captures multi-tenant requests (e.g., ) and routes them to the Gateway Node.

### Key Routing Features:

- SSL Termination: All traffic is upgraded from HTTP (80) to HTTPS (443).
- WebSocket Support: Critical for Vite HMR, PeerJS signaling, and the Gateway Node. This is achieved using and headers.
- Tenant Identification: For wildcard subdomains, Nginx is designed to allow the Gateway to identify which tenant context the request belongs to via host-based routing.

For a deep dive into the routing logic and proxy headers, see [Nginx Reverse Proxy and Routing](#2.1).

## TLS and PKI Configuration

To ensure secure communication and allow browser features like WebRTC and Web Crypto to function correctly, the backbone employs a local Public Key Infrastructure (PKI).

The setup relies on:

- Self-Signed Root CA: A trusted local certificate authority.
- Wildcard Certificates: Generated to cover both the base domain and all subdomains ().
- Nginx Integration: Certificates are mounted into the Nginx container at [apps/backbone/docker-compose.yaml#30](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/docker-compose.yaml#L30-L30)

For instructions on generating these certificates and trusting the CA in your browser, see [TLS/PKI Configuration](#2.2).

## Data Layer: MongoDB

MongoDB serves as the central source of truth for the Org API. It stores structured data across three main collections:

1. Users: Credentials and node identification.
2. Functions: User-defined serverless code.
3. Key-Value (KV): Metadata and encrypted payloads for the distributed store.

The service is configured with root credentials ( / ) [apps/backbone/docker-compose.yaml#11-12](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/docker-compose.yaml#L11-L12)
