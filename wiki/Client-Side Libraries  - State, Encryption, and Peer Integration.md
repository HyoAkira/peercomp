## Client-Side Libraries: State, Encryption, and Peer Integration

Relevant source files

This section details the client-side infrastructure of the PeerComp web application. It covers global state management using Zustand, the offloading of cryptographic operations to Web Workers, persistent browser storage via Dexie (IndexedDB), and the lifecycle management of the P2P node within the React component tree. It also details the identity key management system used for secure communication.

## State Management with Zustand

The application utilizes Zustand for lightweight, reactive state management. Several specialized stores handle authentication tokens, identity keys, UI notifications, and distributed network entities.

## Encryption and Web Crypto Worker

To maintain high performance and UI responsiveness, cryptographic operations are offloaded to a Web Worker. This worker leverages the Web Crypto API for secure key generation, signing, and encryption.

### Cryptographic Protocols

1. Identity (ECDSA): Uses the curve to generate identity keys for signing and verifying public keys to prevent Man-in-the-Middle (MITM) attacks.
2. Key Exchange (ECDH): Facilitates secure shared secret derivation between peers.
3. Data Encryption (AES-GCM): Uses 256-bit AES in Galois/Counter Mode for authenticated encryption of KV values. A unique 12-byte IV is generated for every encryption operation.
