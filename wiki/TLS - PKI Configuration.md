## TLS/PKI Configuration

Relevant source files

- [apps/backbone/docker-compose.yaml](https://github.com/HyoAkira/bitirme2/blob/7a5d8555/apps/backbone/docker-compose.yaml)

This page details the Public Key Infrastructure (PKI) and Transport Layer Security (TLS) setup for the PeerComp platform. To facilitate local development with valid HTTPS across multiple services and wildcard subdomains (e.g., ), the project utilizes a custom Root Certificate Authority (CA) and locally-trusted leaf certificates.

## Infrastructure Overview

The PeerComp local environment relies on a two-tier certificate hierarchy. This ensures that the Nginx reverse proxy can terminate SSL for any service or dynamically generated tenant subdomain while remaining trusted by the developer's browser. The backbone infrastructure manages these assets through Docker volumes.

### PKI Components

| Component | File Path | Role |
| --- | --- | --- |
| Root CA Key |  | The private key used to sign the Root CA certificate. |
| Root CA Cert |  | The self-signed certificate that must be imported into the browser/OS trust store. |
| Leaf Private Key |  | The private key used by the Nginx server for SSL termination. |
| Leaf Certificate |  | The certificate presented to clients, signed by the mkcert development CA. |
| OpenSSL Config |  | Configuration defining Subject Alternative Names (SAN) for wildcard support. |
